API design meets an everyday business app

Inventory Receiving

A React receiving desk backed by an ASP.NET Core API. Receive stock, correct a count, and answer the inevitable “wait, did we already enter that?”

The interesting bit: a retry returns the original receipt. A changed payload gets a clear conflict. Neither quietly adds extra stock.

  • ASP.NET Core
  • REST API
  • OpenAPI
  • React / TypeScript
  • SQLite
Inspect the API ↗Run the HTTP examplesExplore the repository ↗
What’s worth a closer look?

Transactions keep receipt lines together. The generated OpenAPI contract describes request constraints and Problem Details responses. Stock corrections require the version the caller read; stale updates return 409.

Independent local demo with invented stock. The hosted API explorer is read-only; request execution runs in the local app.

Label Review

Compare two product labels, see what changed, and give unclear readings the human attention they deserve.

The interesting bit: AI reads the evidence. Code compares it. A person checks the originals.

What’s worth a closer look?

Extraction separates readable, absent, and unclear content. The comparison preserves changes to numbers, units, and ingredient order. An unclear reading stays flagged after review.

The no-key sample uses prepared fixtures. Live AI requires your own API account; paid extraction accuracy has not been evaluated. Runs locally.

Integrations that recover

Reliable Sync

Consume a paged HTTP API, handle a rough patch, and resume from the last committed page without counting an event twice.

  • .NET
  • HTTP API client
  • SQLite
What’s worth a closer look?

Retries have limits. Data and checkpoints commit together. Replayed events are recognized, and invalid data stops the run before it can corrupt the next page.
